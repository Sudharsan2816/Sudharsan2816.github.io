What I build

$ cat capabilities.md

The parts of an AI system I work on, each with the work that proves it. Production work is at Edvoy; the rest is public code you can read and run.

  • 01RAG

    RAG pipelines

    chunkingembeddingsFAISSrerankingrelevance thresholdscitationsfollow-up rewriting

    Fixed vs semantic chunking benchmarked on 32 labelled questions: 100% vs 90.6% complete-hit@3. FAISS fetches 20 and a reranker keeps 6; a similarity floor makes it refuse instead of guess. RAG over email threads runs in production at Edvoy.

    Market Research Copilot →In production →

  • 02AGENTS

    LLM agents and workflows

    LangGraphn8nHermesstate machineshuman-in-the-loopdecision rules

    Designed the architecture of a production AI workflow system at Edvoy (n8n + Hermes + LangGraph), with guardrails and a decision directory that decide when to act and when to alert a person. Built a LangGraph review agent whose approval gate is a real branch in the graph.

    At Edvoy →Code Review Agent →

  • 03EVALS

    Evaluation

    hit@kMRRrecall@kcitation precisionfaithfulness checksregression suiteslive tests

    Five evaluation reports committed with the code. A RAG regression suite gates CI, and a live test caught three failures that were fixed and retested 10 of 10. 147 automated tests run in CI across three builds. In production, every run of the application automation is counted: about 95% succeed.

    The reports →Copilot results →

  • 04GUARDRAILS

    Guardrails and AI security

    groundingprompt-injection screeningrole-based retrievalredactionaudit logsHMAC webhooks

    Model findings must quote a changed line or they are dropped, and the verdict is computed in code. Permissions are enforced inside the retrievers, so restricted data never reaches the model: 7 of 7 allow and deny cases pass.

    Permission-Aware RAG →

  • 05BACKEND

    Production backend for LLM apps

    Pythonasync FastAPIRabbitMQGCP Pub/SubidempotencyretriesDockerAWSMongoDB

    At Edvoy: a RabbitMQ pipeline with 3,400+ submissions across 70+ university portals, split into three containers so one failing feature can’t take the whole system down; before that, 25+ ETL pipelines and a Pub/Sub event service. In public code: one review per commit, however often a webhook arrives.

    Application automation →Pipelines →

  • 06LLM APIS

    LLM APIs and providers

    Claude APIOpenAI APINVIDIA NIMGemini APIprompt cachingtimeouts and fallbacks

    One interface over Claude, OpenAI and NVIDIA, with a single time bound per call. When an endpoint fails, embeddings fall back to a local model and the reranker to embedding order.

    Provider layer →Fallbacks →
